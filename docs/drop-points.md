# Vanilla Drop-Point Catalog

`reference/world/drop-points.json` is the checked authoring index for native
Cyberpunk 2077 drop-point kiosks. It is generated by
`tools/index_drop_points.py`; edit the small reviewed curation file instead of
hand-editing the generated manifest.

## What Is Known

The 2026-07-22 base-game scan found:

- 103 physical entities using
  `base\gameplay\devices\drop_points\drop_point.ent`;
- 101 source streaming sectors;
- 99 entity positions represented in the cooked Night City mappin resource;
- 98 positions in the canonical cooked multi-mappin sets;
- one additional mappin-backed kiosk, Kabuki `drop_point_009`;
- one runtime-verified, street-accessible candidate (`drop_point_009`);
- one rejected candidate (`drop_point_004`), which led into inaccessible
  building geometry during the delivery test;
- one missing orientation. WolvenKit 8.17.4 cannot serialize the Corpo Plaza
  `drop_point_003` sector because of an unrelated
  `WindowBlindersControllerPS.windowBlindersSkillChecks` RTTI mismatch. Its
  NodeRef comes from the CR2W binary string table and its exact position comes
  from the cooked multi-mappin data.

These categories are deliberately distinct:

- `physical_entities` means a real native `DropPoint` entity exists.
- `mappin_evidence.backed` means its exact position occurs in
  `03_night_city.mappins`. It does not prove that the marker is always visible.
- `accessibility=verified` means the kiosk was reviewed in game.
- `selection_eligible` requires reviewed accessibility and suitable mappin
  evidence. Random selection defaults to this safe pool.

The physical index is exhaustive for the scanned game build. The safe random
pool is intentionally not exhaustive: every additional kiosk should be checked
for a public route, usable console face, and unobstructed interaction before it
is marked `verified` in `reference/world/drop-points-curation.json`.

## Native Marker And Navigation Slots

The serialized native template
`base\gameplay\devices\drop_points\drop_point.ent` explains why placing a
custom static marker at the entity root makes its HUD icon appear near the
floor. Its `UI_Slots` component starts `0.5` units above the root and the
`UI_Interaction` slot adds another `1.5`, for a final two-unit vertical
offset. The same template provides:

- `poi_mappin` at local `(-0.1, 0.8, 1.9)` after the component offset;
- `roleMappin` at local `(-0.2, 0.75, 1.08)` after the component offset;
- `main_slot/navQuery` at local `(0, 1.3, 1.0)`.

Native entity references can resolve these slots directly. Ghostline's
always-loaded delivery marker cannot, so its journal map pin explicitly uses a
two-unit Z offset while preserving the native device root X/Y used by the
cooked GPS data. Do not treat a vertical marker offset as a substitute for
clearing stale GPS state between objectives.

## Query And Select

List only reviewed candidates:

```powershell
py -B .\tools\index_drop_points.py list
```

List every physical Watson/Kabuki entity, including unsafe and unreviewed
ones:

```powershell
py -B .\tools\index_drop_points.py list `
  --include-unvetted --region watson --area kabuki
```

Choose deterministically from the reviewed pool:

```powershell
py -B .\tools\index_drop_points.py choose --seed gq001
```

`choose` is an authoring helper. Runtime random selection still needs quest
graph branches that keep each selected NodeRef, native reservation event, and
objective marker in sync. Do not randomly select a device independently from
its journal mappin.

## Rebuild Provenance

The authoritative world source is
`archive\pc\content\basegame_3_nightcity.archive`. The audit extracted all
23,691 `.streamingsector` resources, byte-filtered them for the native
drop-point entity-template path, and serialized the 101 matching sectors.
The exact source resources are recorded in the generated manifest.

After extracting and serializing those matching sectors and
`base\worlds\03_night_city\_compiled\default\03_night_city.mappins`, rebuild
with:

```powershell
py -B .\tools\index_drop_points.py build `
  --sectors H:\Ghostline-audits\drop-point-index-20260722\raw-sectors `
  --mappins H:\Ghostline-audits\drop-point-access-20260722\raw\03_night_city.mappins.json
```

The builder also scans `reference/journal` for vanilla quest references and
records matching source files per entity. Its output is replaced atomically.

Validate the tool and checked manifest with:

```powershell
py -B -m unittest tests.test_index_drop_points -v
```
